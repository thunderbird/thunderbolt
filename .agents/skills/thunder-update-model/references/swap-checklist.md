# Swap checklist

The implementer's contract for `/thunder-update-model`. Work through every item in order and report
each one as done or not applicable, with the path you touched. Scope tags: universal (every swap),
same-id (the row keeps its id), fresh-id (a new id), confidential (`provider: 'tinfoil'`), direct
(`provider: 'thunderbolt'`), new-provider (stop and report). The confidential and direct tags on
items 12 and 13 apply to whichever of the two models is on that route; items 16 and 17 follow
the incoming model's route, and the leaving model's compatibility entries stay as they are. The slug is the
`model` field, the uuid is the row `id`, the export constant is the `defaultModel*` symbol, and the
internal name is what the upstream sees (`claude-opus-5`, `accounts/fireworks/models/<name>`).

Guardrails: never edit an existing migration SQL or snapshot under `backend/drizzle/`;
`_journal.json` only gains the new entry. Never edit `CHANGELOG.md` (generated by
`scripts/create-release.ts`) or any `.po` catalog (model names are reconciled by hash, never
translated). Never run bare `bun test` at the repo root. Pin pi-ai where it is: items 16 and 17
alias a model Pi's catalog lacks, and a dependency bump ships as its own PR. Never commit; the
developer runs `/thunderpush`.

`AGENTS.md` (Testing, After Each Task), `backend/docs/testing.md` and
`docs/internals/development/testing.md` bind every test the swap touches; read them before writing
one. A swap test proves a behaviour the application depends on, such as:

- the request body sent for the incoming slug at each reasoning level;
- the price row the admission check finds for the upstream identity;
- the fallback the no-header path picks;
- the lineage moving an edited row off the retired slug.

A test that restates its fixture or asserts a constant against itself adds nothing. Derive fixtures
from `defaultModels` and the real profiles rather than hardcoded ids and names, so the next swap
carries them along. Inject dependencies instead of calling `mock.module`, run backend tests on the
PGlite harness (`createTestDb`), and look in `src/test-utils/` and `backend/src/test-utils/` before
writing a new mock.

## A. Catalog, `shared/defaults/models.ts`

1. universal. same-id: edit the leaving model's export in place (`name`, `model`, `vendor`,
   `description`, `contextWindow` per the developer's decision, `url` if it changes) and keep the
   `id`. fresh-id: add a new `SharedModel` export with a fresh UUIDv7
   (`bun -e 'console.log(Bun.randomUUIDv7())'`) and remove the leaving model's. `provider` is
   transport (`thunderbolt` direct, `tinfoil` confidential); `vendor` is branding and drives Pi
   compatibility, vision rules and Anthropic routing (item 17). Done when the row exists with every
   field filled and `toolUsage: 1`.
2. universal. Name the export constant `defaultModel` plus the incoming display name in PascalCase
   without spaces or punctuation: Kimi K3 (`kimi-k3`) becomes `defaultModelKimiK3`, like
   `defaultModelGlm53Flash` and `defaultModelOpus5`. On a same-id swap this is a rename.
   `defaultModel<Incoming>` elsewhere in this checklist means that name. tsc lists every importer:
   profiles, eval, e2e, backend, lineage, `src/defaults/automations.ts`. Done when
   `bun run type-check` passes.
3. universal. `defaultModels` order is picker order and feeds the snapshot hash and
   `managed-models.test.ts`. fresh-id: add the incoming model, drop the leaving one. Done when it
   lists exactly the shipped models.
4. universal. Repoint `defaultModelId` off the leaving model. Done when it names a shipped model.
5. confidential, leaving half. The `defaultModels` JSDoc lists the legacy slugs the backend
   accepts; add the leaving model's slug when it was confidential (a direct slug is not kept, see
   item 13). Done when the comment matches `legacyConfidentialModels`.
6. universal. `defaultModelImageSupport`, keyed by the incoming model's id: `'supported'` iff
   `image` is in its `modalities.input` and the provider catalog agrees; `models.test.ts` fails
   without an entry. fresh-id: drop the leaving model's entry. Done when each default has one entry.
7. universal. Bump `defaultModelsVersion` by one. Done when the constant is higher than on `main`.
8. universal. Snapshot test: run `bun test shared/defaults --timeout 5000`, paste the new
   `version`, `hash` and `metadataHash` into `expected` in `shared/defaults/models.test.ts`, then
   update the identity assertions (ids, slugs, vendors by name) and the image-support cases. Done
   when the file passes.

## B. Profiles and lineage

9. universal. One profile per model in `src/defaults/model-profiles/<incoming-profile>.ts` (a short
   kebab name, as `glm-flash.ts`), keyed `modelId: defaultModel<Incoming>.id`.
   `providerOptions.reasoningEffort` sets reasoning per model. Managed confidential models always
   request reasoning, so a missing or `null` value means `medium`, not off; `reasoningEffort: 'off'`
   turns it off. same-id: rename the profile file and constant to match the incoming model.
   fresh-id: new file, delete the leaving model's. Both: update
   `src/defaults/model-profiles/index.ts` (`defaultModelProfiles`) and
   `src/defaults/model-profiles.ts`. OTA drops a model without a bundled profile, so a fresh id
   always needs a client build. Done when `bun test src/defaults --timeout 5000` passes.
10. same-id. `modelLineages` in `src/lib/data-migrations/upgrade-model-defaults.ts`: append the
    leaving model's slug to `legacySlugs` and its display name to `legacyNames` on the lineage whose
    `target` is the incoming model's export; the lineage also carries `vendor`, `description` and
    `contextWindow`, so a vendor change rides along. Update `upgrade-model-defaults.test.ts` and the
    lineage table in `src/lib/reconcile-defaults.test.ts`. Done when both tests pass.
11. fresh-id. No lineage. Check that `src/defaults/automations.ts` (`modelId: defaultModelOpus5.id`)
    and `src/dal/models.test.ts` (fallback to `defaultModelId`) still point at a shipped id. Done
    when `bun test src/dal/models.test.ts src/defaults --timeout 5000` passes.

## C. Backend route and price

Items 12 and 13 each have a leaving half and an incoming half. When both models share a route, the
other item is not applicable.

12. confidential, in `backend/src/inference/managed-models.ts`. Leaving half, when the leaving
    model is confidential: append its slug to `legacyConfidentialModels` (receipts issued before
    the deploy, edited rows, old builds). If the no-header fallback in
    `backend/src/tinfoil/routes.ts` pointed at the leaving model, choose the new fallback export.
    Done when the leaving model still resolves as legacy in `managed-models.test.ts`. Incoming
    half, when the incoming model is confidential: nothing to add, the allowlist derives from
    `defaultModels`. Done when `managed-models.test.ts` lists the incoming model among the
    confidential slugs.
13. direct, in the same file. Leaving half, when the leaving model is direct: its
    `managedDirectRuntimes` entry leaves with it, because `managed-models.test.ts` asserts that
    `Object.keys(managedDirectRuntimes)` equals the non-confidential default slugs exactly. Direct
    slugs have no legacy map, so an old client still sending the leaving model's slug gets "Model
    not found"; say so in the report. Incoming half, when the incoming model is direct: add
    `managedDirectRuntimes[<incoming-slug>]` with `provider`, `internalName`, `supportsStreamUsage`
    and `omitTemperature`. `getInferenceClient` (`backend/src/inference/client.ts`) has `anthropic`
    and `fireworks` clients, and `ManagedDirectRuntime.provider` admits only `'anthropic'`, so a
    Fireworks runtime widens that union; a vendor with no client is new-provider work (item 25).
    Done when the parity test passes.
14. universal. Price row, the quota lever: `checkManagedInferenceAdmission` in `usage-ledger.ts`
    prices every request; a missing row returns 503 `INFERENCE_PRICE_UNAVAILABLE`. Run
    `cd backend && bun db generate --custom --name=seed-<provider>-<model>-price` and paste into
    the generated SQL:

   ```sql
   -- QUOTA price inherited from <leaving-slug> (<in>/<out>), deliberately not the provider list price.
   INSERT INTO "inference_prices" ("provider", "model", "input_nano_usd_per_token", "output_nano_usd_per_token")
   VALUES ('<provider>', '<model>', <in>, <out>)
   ON CONFLICT ("provider", "model") DO NOTHING;
   ```

   The `provider` and `model` columns name the upstream identity, never the catalog's `provider`
   field (a `thunderbolt` row is never looked up): confidential rows are `('tinfoil', <public
   slug>)`; direct rows are `(<runtime provider>, <internalName>)` from the incoming model's
   `managedDirectRuntimes` entry. Copy the leaving model's numbers from its own seed migration;
   `0029` is the precedent and its comment states the policy (`0033` seeded Fireworks list prices
   for rows that never shipped and is no precedent for a swap). Keep the SQL,
   `meta/00NN_snapshot.json` and the new `_journal.json` entry together in the change; a migration
   numbered by hand with an older `when` is silently skipped. If the number collides with `main`,
   remove only this change's SQL, snapshot and journal entry, then regenerate. Done when
   `grep -n '<model>' backend/drizzle/*.sql` shows the row and `_journal.json` ends with its tag.
15. universal. Backend fixtures that pin slugs: `managed-usage.integration.test.ts` (price oracle)
    and `tinfoil/routes.test.ts` (receipt price table and header-acceptance list: add the incoming
    model, keep the leaving model), both under `backend/src/`, plus
    `backend/src/api/health.test.ts`. Done when `bun run test:backend` passes (item 24).

## D. Pi compatibility, `shared/agent-core/confidential-model.ts`

16. confidential. `modelAliases` maps the slug onto a Pi catalog id and `vendorAliases` maps the
    vendor (`zhipu` to `zai`); no entry means `compatibility-missing` and every send throws
    locally. Read the catalog first:

   ```bash
   jq -r '.. | objects | .id? // empty' node_modules/@earendil-works/pi-ai/dist/providers/data/<pi-vendor>.json | sort -u
   jq '.. | objects | select(.id? == "<pi-id>") | .thinkingLevelMap' node_modules/@earendil-works/pi-ai/dist/providers/data/<pi-vendor>.json
   ```

   Use the exact Pi catalog id the first jq prints (zai ids use dots, `glm-5.2`; deepseek ids use
   dashes, `deepseek-v4-flash`). If the incoming model's Pi catalog id is listed, add no alias;
   remove an alias or a `thinkingLevelMap` override that only stood in for the missing catalog
   entry, and keep a `compat` or effort-map override that matches the provider's documented body
   (Tinfoil `reasoning_params`) together with its request-body test. If it is absent, alias it to
   the closest listed Pi catalog id (same vendor, same tier, newest version Pi lists:
   `deepseek-v4-1-flash` aliases `deepseek-v4-flash`; never across vendors or tiers) and refresh the
   comment above `modelAliases` so it names the missing slug and the pi-ai version from
   `package.json`. In both cases keep the leaving model's alias, when it has one. Then compare the
   `thinkingLevelMap` of the incoming model's entry (or of the alias target) with the profile's
   `reasoningEffort`. Pi's `clampThinkingLevel` silently swaps a level mapped to `null` for the
   nearest supported one (Pi's deepseek entries map `minimal`, `low` and `medium` to `null`). Set
   the override's `thinkingLevelMap` from the provider's `effort_map` for every Pi level, as the
   `deepseek-v4-1-flash` branch in `resolveConfidentialModelCompatibility` does, so no level
   silently clamps. Compare the body Pi emits with the provider's documentation. Tinfoil documents
   it in `reasoning_params` (`effort_map` plus the enable and disable shapes). DeepSeek nests them
   under `chat_template_kwargs`, while Pi's deepseek format sends top-level `thinking` and
   `reasoning_effort`. A mismatch needs a Pi `compat` override. Add a case to
   `confidential-model.test.ts`, modelled on `uses catalog-driven Pi thinking metadata`, asserting
   the request body for the incoming model's slug with reasoning off, on, and at each effort level,
   and, when a `compat` override changed the body shape, that the fields Pi would otherwise send
   are absent (`not.toHaveProperty`, as the `deepseek-v4-1-flash` case does).
   Report `experimental` from the provider catalog. Done when `bun run test:agent-core` and
   `bun run test:agent-core:browser` pass.
17. direct. Anthropic vendor, the direct-route twin of item 16 (other vendors use
    `openai-compat-model.ts`, which has no catalog): run item 16's jq with `<pi-vendor>` =
    anthropic. If `claude-<incoming-slug>` is listed, add no alias and remove any alias an earlier
    swap left for it. If it is absent, `src/acp/built-in-adapter.ts` derives `catalogModelId` by
    string (`` `claude-${model.model}` ``) and returns null when `isKnownAnthropicModel` rejects it,
    so the chat silently drops to the legacy pipeline. Alias the slug to the closest listed id (item
    16's definition) and follow item 16's rules for the pi-ai version comment and the leaving
    model's alias: add the alias table next to the `claude-` derivation in `built-in-adapter.ts` and
    keep the real slug as the wire `modelId`. `buildAnthropicModel`
    (`shared/agent-core/anthropic-model.ts`) needs no change: it reads `thinkingLevelMap`, `compat`
    and pricing from the `catalogModelId` entry, and `id`, `baseURL` and `contextWindow` from the
    descriptor. Compare the target's `thinkingLevelMap` with the profile's `reasoningEffort` as in
    item 16. The direct route has no per-slug override: when the target's `thinkingLevelMap` or
    `compat` mismatches the profile or the provider's documentation, stop and report it to the
    developer. Assert the incoming slug's wire id and catalog id in the managed Anthropic case of
    `src/acp/built-in-adapter.test.ts`, and its request body at each reasoning level in a
    `shared/agent-core/anthropic-model.test.ts` case modelled on
    `uses the native Messages API and enables prompt caching for a managed wire alias`. Done when
    `bun test src/acp/built-in-adapter.test.ts --timeout 5000` and `bun run test:agent-core` pass.
18. universal. `/config` publishes the row to every client once the backend deploys, while older
    clients keep their bundled compatibility table. A slug with no `modelAliases` entry throws
    `compatibility-missing` the moment the row arrives (PR #1269, builds 0.1.128 and 0.1.129); a
    changed `thinkingLevelMap` or Pi `compat` override the old client lacks throws nothing and
    yields wrong request bodies (reasoning off or rejected). The backend cannot redirect a
    confidential slug: the body is HPKE-sealed and only the enclave reads the model inside it, so
    older builds are retired with `MIN_APP_VERSION`. A client-side change makes the row incompatible
    with older builds: compatibility code from item 16 (`modelAliases`, `thinkingLevelMap`, a Pi
    `compat` override) or an item 17 alias (older builds fall back to the legacy pipeline without an
    error), a profile under a new id, or a changed profile value (`reasoningEffort`,
    `toolsOverride`). Renaming a profile file or constant changes nothing for old clients, since
    profiles reconcile by `modelId`. After such a change the order is: release the clients, set
    `MIN_APP_VERSION` to that release, then deploy the backend. Done when the report lists every
    client-side change, names the order, the first client version that carries those changes, and
    that version as the `MIN_APP_VERSION` value.

## F. Blast-radius grep, verification and new provider

23. universal. Run, with the leaving model's values (`<leaving-pi-alias>` is the leaving model's
    `modelAliases` target, if any):

   ```bash
   git grep -n -i -e "<leaving-slug>" -e "<leaving-display-name>" -e "<leaving-uuid>" -e "defaultModel<Leaving>" -e "<leaving-pi-alias>" -- . ':!*.po' ':!bun.lock' ':!CHANGELOG.md'
   ```

   Classify every hit:

   - change: still describes the live catalog;
   - legacy-keep: compat that must survive and often grow (`legacyConfidentialModels`,
     `modelAliases`, `modelLineages`, the `defaultModels` JSDoc, old price rows and the tests
     pinning them);
   - historical: fixtures across `backend/`, `shared/agent-core/`, `cli/`, `src/settings/models/`
     and `scripts/agent-core-browser-check.ts` that use old slugs as arbitrary data and keep
     working only while the legacy alias exists; docs history; look-alikes such as the CLI's BYOK
     `zai: 'glm-5.2'` default in `cli/src/agent/defaults.ts`;
   - current identity (same-id only): the uuid and the lineage target stay live.

   Done when no hit is left in the change class and the report lists the other three classes with
   paths.
24. universal. During implementation, run only the scoped Done commands
    (`bun test <path> --timeout 5000`, the single-file checks). At the end, run each workspace
    suite once from the worktree root; the Done criteria of items 15, 16, 19 and 21 name a
    workspace suite and are checked in this final run:

   ```bash
   bun run type-check && bun run lint
   bun run test
   bun run test:agent-core
   bun run test:agent-core:browser
   bun run test:backend
   cd cli && bun run typecheck && bun run test && cd ..
   ```

   `test:agent-core:browser` is needed when `shared/agent-core/**` changed; the backend suite runs
   on in-memory PGlite from its preload (`backend/docs/testing.md`), no database to start;
   `bun run i18n:check` only if a UI string changed. Done when every command exits 0; paste the tail
   of each into the report. When provider credentials are available locally, send one text message,
   one image message and one tool-calling message through the app with the incoming model and record
   the outcome in the report.
25. new-provider. A vendor with no client in `getInferenceClient` needs a settings key with its
    env, Helm and Pulumi mirrors (grep `fireworksApiKey` and `FIREWORKS_API_KEY` for the five
    files), a client, and env on Render before the backend deploys: integration work outside this
    checklist. Done when you have reported it and stopped.

## Deploy note for the report

Without a client-side change (as defined in item 18), deploy the backend first or together with
the clients. The price migration runs at backend boot on Render, so the row exists before any
client asks; a same-id swap reaches old clients OTA because `/config` publishes
`shared/defaults/models.ts` with its version. With a client-side change, use the rollout order
from item 18 instead. A new client against an old backend gets "Model not found"
or is priced as the fallback model. After deploy,
`curl -H "Authorization: Bearer $MONITORING_TOKEN" "https://<api>/v1/health/models?model=<incoming-slug>"`
probes the price row and a real completion; it bypasses the client's Pi compatibility path.
Production alerting in Better Stack polls that URL per built-in model; list the monitor to add
(`?model=<incoming-slug>`) and the one to retire (`?model=<leaving-slug>`), changed in the same
window as the backend deploy.
