# Swap checklist

The implementer's contract for `/thunder-update-model`. Work through every item in order and report
each one as done or not applicable, with the path you touched. Scope tags: universal (every swap),
same-id (the row keeps its id), fresh-id (a new id), confidential (`provider: 'tinfoil'`), direct
(`provider: 'thunderbolt'`), new-provider (stop and report). Pointers are symbol plus path. X is
the leaving model, Y the incoming one. The slug is the `model` field, the uuid is the row `id`, the
export constant is the `defaultModel*` symbol, and the internal name is what the upstream sees
(`claude-opus-5`, `accounts/fireworks/models/<name>`). This workflow replaces X with Y; it never
leaves both in the catalog.

Guardrails: never edit an existing migration SQL or snapshot under `backend/drizzle/`;
`_journal.json` only gains the new entry. Never edit `CHANGELOG.md` (generated by
`scripts/create-release.ts`) or any `.po` catalog (model names are reconciled by hash, never
translated). Never run bare `bun test` at the repo root. Never commit; the developer runs
`/thunderpush`.

## A. Catalog, `shared/defaults/models.ts`

1. universal. The row. same-id: edit X's export in place (`name`, `model`, `vendor`, `description`,
   `contextWindow` per the developer's decision, `url` if it changes) and keep the `id`. fresh-id:
   add a new `SharedModel` export with a fresh UUIDv7 (`bun -e 'console.log(Bun.randomUUIDv7())'`)
   and remove X's. `provider` is transport (`thunderbolt` direct, `tinfoil` confidential); `vendor`
   is branding and drives Pi compatibility, vision rules and Anthropic routing (item 17). Done
   when the row exists with every field filled and `toolUsage: 1`.
2. universal. Rename the export constant to match Y (`defaultModelGlm53Flash` is named for its
   model). tsc lists every importer: profiles, eval, e2e, backend, lineage,
   `src/defaults/automations.ts`. Done when `bun run type-check` passes.
3. universal. `defaultModels` order is picker order and feeds the snapshot hash and
   `managed-models.test.ts`. fresh-id: Y in, X out. Done when it lists exactly the shipped models.
4. universal. `defaultModelId`: repoint it if X was the default. Done when it names a shipped model.
5. universal. The JSDoc above `defaultModels` lists the legacy slugs the backend accepts; add X's
   slug. Done when the comment matches `legacyConfidentialModels` and the direct runtimes.
6. universal. `defaultModelImageSupport[Y.id]`: `'supported'` iff `image` is in Y's
   `modalities.input` and the provider catalog agrees; `models.test.ts` fails without an entry.
   fresh-id: drop X's entry. Done when every default has exactly one entry.
7. universal. Bump `defaultModelsVersion` by one; a profile-only edit needs it too. Done when the
   constant is higher than on `main`.
8. universal. Snapshot test: run `bun test shared/defaults --timeout 5000`, paste the new
   `version`, `hash` and `metadataHash` into `expected` in `shared/defaults/models.test.ts`, then
   update the identity assertions (ids, slugs, vendors by name) and the image-support cases. Done
   when the file passes.

## B. Profiles and lineage

9. universal. One profile per model in `src/defaults/model-profiles/<y>.ts`, keyed
   `modelId: defaultModelY.id`. `providerOptions.reasoningEffort` is the per-model reasoning knob:
   `readProfileThinkingLevel` in `src/acp/built-in-adapter.ts` turns it into a Pi thinking level
   that the harness maps onto the wire. Managed confidential models always request reasoning
   (`reasoning: true`) and a profile with no level falls back to `medium`, so a missing or `null`
   value leaves reasoning on; `reasoningEffort: 'off'` turns it off (`'max'` is also accepted).
   same-id: rename the profile file and constant to match Y. fresh-id: new file, delete X's. Both:
   update `src/defaults/model-profiles/index.ts` (`defaultModelProfiles`) and
   `src/defaults/model-profiles.ts`. OTA drops a model without a bundled profile, so a fresh id
   always needs a client build. Done when `bun test src/defaults --timeout 5000` passes.
10. same-id. `modelLineages` in `src/lib/data-migrations/upgrade-model-defaults.ts`: append X's
    slug to `legacySlugs` and X's display name to `legacyNames` on the lineage whose `target` is
    Y's export; the lineage also carries `vendor`, `description` and `contextWindow`, so a vendor
    change rides along. Update `upgrade-model-defaults.test.ts` and the lineage table in
    `src/lib/reconcile-defaults.test.ts`. Done when both tests pass.
11. fresh-id. No lineage. Check that `src/defaults/automations.ts` (`modelId: defaultModelOpus5.id`)
    and `src/dal/models.test.ts` (fallback to `defaultModelId`) still point at a shipped id. Done
    when `bun test src/dal/models.test.ts src/defaults --timeout 5000` passes.

## C. Backend route and price

Items 12 and 13 each have a leaving half and an incoming half. Run the leaving half for X's route
and the incoming half for Y's route; when both models share a route, both halves of that item
apply and the other item is not applicable.

12. confidential, in `backend/src/inference/managed-models.ts`. Leaving half (X confidential):
    append X's slug to `legacyConfidentialModels` (receipts issued before the deploy, edited rows,
    old builds); if the export that the no-header fallback in `backend/src/tinfoil/routes.ts`
    imports was renamed, repoint it. Done when X still resolves as legacy in
    `managed-models.test.ts`. Incoming half (Y confidential): nothing to add, the allowlist derives
    from `defaultModels`. Done when `managed-models.test.ts` lists Y among the confidential slugs.
13. direct, in the same file. Leaving half (X direct): X's `managedDirectRuntimes` entry leaves with
    X; `managed-models.test.ts` asserts that `Object.keys(managedDirectRuntimes)` equals the
    non-confidential default slugs exactly, there is no legacy map for direct slugs, and an old
    client still sending X's slug gets "Model not found" (say so in the report). Incoming half (Y
    direct): add `managedDirectRuntimes[<y-slug>]` with `provider`, `internalName`,
    `supportsStreamUsage` and `omitTemperature`. `getInferenceClient`
    (`backend/src/inference/client.ts`) has `anthropic` and `fireworks` clients, and
    `ManagedDirectRuntime.provider` admits only `'anthropic'`, so a Fireworks runtime widens that
    union; a vendor with no client is new-provider work (item 25). Done when the parity test passes.
14. universal. Price row, the quota lever (`checkManagedInferenceAdmission` in `usage-ledger.ts`
    prices every request; a missing row returns 503 `INFERENCE_PRICE_UNAVAILABLE`). Run
    `cd backend && bun db generate --custom --name=seed-<provider>-<model>-price` and paste into
    the generated SQL:

   ```sql
   -- QUOTA price inherited from <x-slug> (<in>/<out>), deliberately not the provider list price.
   INSERT INTO "inference_prices" ("provider", "model", "input_nano_usd_per_token", "output_nano_usd_per_token")
   VALUES ('<provider>', '<model key>', <in>, <out>)
   ON CONFLICT ("provider", "model") DO NOTHING;
   ```

   Both columns name the upstream identity, never the catalog's `provider` field: confidential
   rows are `('tinfoil', <public slug>)`; direct rows are `(<runtime provider>, <internalName>)`
   from Y's `managedDirectRuntimes` entry, `('anthropic', 'claude-opus-5')` today. A row keyed
   `thunderbolt` is never looked up and every request answers `INFERENCE_PRICE_UNAVAILABLE`. Copy
   X's numbers from its own seed migration; `0029` is the precedent and its comment
   states the policy (`0033` seeded Fireworks list prices for rows that never shipped and is no
   precedent for a swap). Commit the SQL, `meta/00NN_snapshot.json` and the new `_journal.json`
   entry together; a migration numbered by hand with an older `when` is silently skipped. If the
   number collides with `main`, remove only this change's SQL, snapshot and journal entry, then
   regenerate. Done when `grep -n '<model key>' backend/drizzle/*.sql` shows the new row and
   `_journal.json` ends with its tag.
15. universal. Backend fixtures that pin slugs: `managed-usage.integration.test.ts` (price oracle)
    and `tinfoil/routes.test.ts` (receipt price table and header-acceptance list: add Y, keep X),
    both under `backend/src/`, plus `backend/src/api/health.test.ts`. Done when
    `bun run test:backend` passes (item 24).

## D. Pi compatibility, `shared/agent-core/confidential-model.ts`

16. confidential. `modelAliases` maps the slug onto a Pi catalog id and `vendorAliases` maps the
    vendor (`zhipu` to `zai`); no entry means `compatibility-missing` and every send throws
    locally. Read the catalog first:

   ```bash
   jq -r '.. | objects | .id? // empty' node_modules/@earendil-works/pi-ai/dist/providers/data/<vendor>.json | sort -u
   jq '.. | objects | select(.id? == "<pi-id>") | .thinkingLevelMap' node_modules/@earendil-works/pi-ai/dist/providers/data/<vendor>.json
   ```

   Use the exact id the first jq prints (zai ids use dots, `glm-5.2`; deepseek ids use dashes,
   `deepseek-v4-flash`). If Y's id is absent, alias it to the closest listed id and refresh the
   comment above `modelAliases` with the pi-ai version from `package.json` (it still names
   0.80.7). Keep X's alias. Compare the alias target's `thinkingLevelMap` with the profile's
   `reasoningEffort`: a level mapped to `null` is unsupported and Pi's `clampThinkingLevel`
   silently substitutes the nearest supported level (Pi's deepseek entries map `minimal`, `low`
   and `medium` to `null`), so add or extend the per-slug override in
   `resolveConfidentialModelCompatibility` next to the `glm-5-3` branch. Compare the body Pi emits
   with the provider's documentation (Tinfoil `reasoning_params`: `effort_map` plus the enable and
   disable shapes; DeepSeek nests them under `chat_template_kwargs`, Pi's deepseek format sends
   top-level `thinking` and `reasoning_effort`); a mismatch needs a Pi `compat` override. Add a
   case to `confidential-model.test.ts`, modelled on `uses catalog-driven Pi thinking metadata`,
   asserting the request body for Y's slug with reasoning off, on, and at each effort level.
   Report `experimental` from the provider catalog. Done when `bun run test:agent-core` and
   `bun run test:agent-core:browser` pass.
17. direct. Anthropic vendor: `src/acp/built-in-adapter.ts` resolves `` `claude-${model.model}` ``
    against Pi's `anthropic.json`, so the slug must exist there with that prefix. Other vendors go
    through `openai-compat-model.ts` with no catalog. Done when
    `bun test src/acp/built-in-adapter.test.ts --timeout 5000` passes.
18. universal. Rollout order. `/config` publishes the row to every client once the backend
    deploys, while older clients keep their bundled compatibility table. A slug with no
    `modelAliases` entry throws `compatibility-missing` the moment the row arrives (PR #1269,
    builds 0.1.128 and 0.1.129); a changed `thinkingLevelMap` or Pi `compat` override the old
    client lacks throws nothing and yields wrong request bodies (reasoning off or rejected). The
    backend cannot redirect a confidential slug: the body is HPKE-sealed and only the enclave reads
    the model inside it, so older builds are retired with `MIN_APP_VERSION` (set by hand on Render
    after the client release ships; `426 Upgrade Required` replaces a mid-chat failure). Any
    client-side change in item 16 (`modelAliases`, `thinkingLevelMap`, a Pi `compat` override, or
    a profile the old build lacks) makes the row incompatible with older builds, so the order is:
    release the clients, set `MIN_APP_VERSION` to that release, then deploy the backend. Done when
    the report lists every client-side change from item 16, names the order, the first client
    version that carries those changes, and that version as the `MIN_APP_VERSION` value.

## F. Blast-radius grep, verification and new provider

23. universal. Run, with X's values:

   ```bash
   git grep -n -i -e "<x-slug>" -e "<X display name>" -e "<x-uuid>" -e "<XExportConstant>" -e "<pi-alias-id>" -- . ':!*.po' ':!bun.lock' ':!CHANGELOG.md'
   ```

   Classify every hit: change (still describes the live catalog), legacy-keep (compat that must
   survive and often grow: `legacyConfidentialModels`, `modelAliases`, `modelLineages`, the
   `defaultModels` JSDoc, old price rows and the tests pinning them), historical (fixtures across
   `backend/`, `shared/agent-core/`, `cli/`, `src/settings/models/` and
   `scripts/agent-core-browser-check.ts` that use old slugs as arbitrary data and keep working only
   while the legacy alias exists; docs history; look-alikes such as the CLI's BYOK `zai: 'glm-5.2'`
   default in `cli/src/agent/defaults.ts`), current identity (same-id only: the uuid and the
   lineage target stay live). Done when no hit is left in the change class and the report lists
   the other three classes with paths.
24. universal. Verification. During implementation, run only the scoped Done commands (`bun test <path> --timeout 5000`, the
    single-file checks); the workspace suites below run once, at the end. Final, once per
    workspace, from the worktree root:

   ```bash
   bun run type-check && bun run lint
   bun run test
   bun run test:agent-core
   bun run test:agent-core:browser
   bun run test:backend
   cd cli && bun run typecheck && bun run test && cd ..
   ```

   `test:agent-core:browser` is needed when `shared/agent-core/**` changed; the backend suite
   runs on in-memory PGlite from its preload (`backend/docs/testing.md`), no database to start;
   `bun run i18n:check` only if a UI string changed. Done when every command exits 0; paste the tail of each into the report. When provider
    credentials are available locally, send one text message, one image message and one
    tool-calling message through the app with Y and record the outcome in the report.
25. new-provider. A vendor with no client in `getInferenceClient` needs a settings key with its
    env, Helm and Pulumi mirrors (grep `fireworksApiKey` and `FIREWORKS_API_KEY` for the five
    files), a client, and env on Render before the backend deploys: integration work outside this
    checklist (Fireworks already has all of it, see item 13). Done when you have reported it and
    stopped.

## Deploy note for the report

When item 16 changed nothing on the client side, deploy the backend first or together with the
clients. The price migration runs at backend boot on Render, so the row exists before any client
asks; a same-id swap reaches old clients OTA because `/config` publishes
`shared/defaults/models.ts` with its version. The row arrives without the compatibility code: a
client older than the build carrying Y's alias, thinking map, `compat` override or profile either
throws `compatibility-missing` on every send or sends a request shape the provider rejects, so
when item 16 changed anything client-side, the rollout order from item 18 applies instead
(clients, then `MIN_APP_VERSION`, then the backend). A new client against an old backend gets
"Model not found" or is priced as the fallback model. After deploy,
`curl -H "Authorization: Bearer $MONITORING_TOKEN" "https://<api>/v1/health/models?model=<y-slug>"`
probes the price row and a real completion; it bypasses the client's Pi compatibility path.
