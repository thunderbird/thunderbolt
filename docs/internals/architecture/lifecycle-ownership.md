# Lifecycle ownership

Asynchronous work must have an owner that decides when it may start, publish a result, and release resources. A fixed sequence of inputs and completion events should produce one defined outcome. Network responses, clocks and operating-system callbacks remain external inputs; reducers do not make those inputs predictable.

## Choosing a model

- Use a reducer for related UI phases and derive values such as button eligibility from that state. Keep independent form fields simple.
- Reserve an attempt synchronously before the first `await`. A disabled button alone does not prevent two handlers from starting in the same render.
- Use a generation or identity check when replacement work can supersede an earlier operation. Check ownership before externally visible effects, not just before rendering the result.
- Use a serial queue when every operation must finish in order. A timeout may stop waiting, but it must not release resources that the timed-out operation still owns.
- Use a terminal latch for an irreversible close/stop transition. All terminal paths must settle waiters and release the same resources exactly once.
- Subscribe to authoritative external state rather than copying it into component state. Do not add a second flag for a phase the existing model already represents.

## Owners and boundaries

| Area                         | Owner                                                                                                                                                                           | Invariant                                                                                                                                                                                                                                                                |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| UI attempts                  | [`useAsyncAttempt`](../../../src/hooks/use-async-attempt.ts)                                                                                                                    | One synchronous reservation owns completion. Unmount suppresses publication; Strict Mode effect replay preserves the reservation. This helper alone does not cancel external work.                                                                                       |
| Authentication               | [`useAuthAttempt`](../../../src/hooks/use-auth-attempt.ts), [`signInWithOtp`](../../../src/lib/sign-in-with-otp.ts), [`signInWithPasskey`](../../../src/lib/passkey.ts)         | Cancellation aborts pending credential requests and rejects late prompt results before verification. Accepted authentication is a commit point: required completion can survive UI unmount. Logout or account replacement still invalidates pending session publication. |
| Sign-in UI                   | [`useSignInFormState`](../../../src/components/sign-in/use-sign-in-form-state.ts), [`useWaitlistState`](../../../src/waitlist/use-waitlist-state.ts)                            | Email sending, verification and passkey work share admission. Resend disables and clears code entry, then restores entry on failure while preserving the original challenge.                                                                                             |
| Session and sync credentials | [`AuthProvider`](../../../src/contexts/auth-context.tsx), [`PowerSync connector`](../../../src/db/powersync/connector.ts)                                                       | Requests and responses retain their account/session identity. Old responses cannot install credentials or clear a replacement session.                                                                                                                                   |
| Database boot/reset          | [`useAppInitialization`](../../../src/hooks/use-app-initialization.ts), [`database facade`](../../../src/db/database.ts)                                                        | Open, close and reset retain ordered storage ownership. Partial opens remain available to cleanup; an expired reset deadline does not release files still being wiped.                                                                                                   |
| Encryption keys              | [`key-store lock`](../../../src/crypto/key-store-lock.ts), [`encryption service`](../../../src/services/encryption.ts)                                                          | Key writers and cleanup share an origin-wide Web Lock. Writer serialization does not turn separate IndexedDB reads into atomic snapshots; readers retain cache invalidation and retry rules.                                   |
| Desktop updates              | [`useDesktopUpdate`](../../../src/hooks/use-desktop-update.ts)                                                                                                                  | Shared status owns check, download and restart admission. Automatic checking is eligible only in the initial phase; explicit retry resumes the failed phase.                                                                                                             |
| OAuth                        | [`useOAuthConnect`](../../../src/hooks/use-oauth-connect.ts), [`MCP OAuth`](../../../src/hooks/use-mcp-server-oauth.ts)                                                         | One attempt owns progress. Authorization success is distinct from a later connection failure.                                                                               |
| Voice                        | [`voice lifecycle`](../../../src/voice/ui/session-lifecycle.ts), [`voice session`](../../../src/voice/session.ts)                                                               | Stop retires the current owner, including startup and microphone acquisition. Late resource acquisition cleans itself up instead of reviving the session.                                                                                                                |
| Chat and transports          | [`ACP adapter`](../../../src/acp/acp-adapter.ts), [`built-in adapter`](../../../src/acp/built-in-adapter.ts), [`WebSocket transport`](../../../src/acp/transports/websocket.ts) | Prompt, permission, compaction and cancellation work remain attached to their session/turn owner. Terminal transport paths settle once; replacement waits for resources it cannot safely share.                                                                          |
| Mini Apps                    | [`document bridge`](../../../src/mini-apps/use-mini-app-bridge.ts), [`approval decisions`](../../../src/mini-apps/mini-app-approval.ts)                                         | Modern document identifiers scope readiness, tools, selection, pending requests and native save replies. Navigation retires the previous document; older guest handshakes are unsupported.                                                                               |
| Backend protected mutations  | [`step-up verification`](../../../backend/src/lib/step-up-otp.ts), [`encryption endpoints`](../../../backend/src/api/encryption.ts)                                             | Verification, protected mutation and successful challenge consumption share a transaction. Failure rolls back consumption; OTP success consumes only its exact challenge.                                                                                                |
| Backend ACP                  | [`Haystack ACP server`](../../../backend/src/haystack/acp-server.ts)                                                                                                            | Resume state belongs to the authenticated user and pipeline. Reattaching a session preserves its live turn owner.                                                                                                                                                        |
| CLI ACP                      | [`harness agent`](../../../cli/src/acp/harness-agent.ts), [`harness runtime`](../../../cli/src/provider-runtime/harness-runtime.ts)                                             | History-affecting changes serialize per session; reasoning persistence completes before replacement history opens. Promise identity prevents an older completion from deleting a newer queue reservation.                                                                |
| Shared event streams         | [`Pi-to-AI-SDK translation`](../../../shared/agent-core/pi-to-aisdk-stream.ts)                                                                                                  | Consumer cancellation uses the Stop finalizer and preserves partial replies without waiting for tool teardown.                                                                                                                                                           |
| Native resources             | [`sidebar webview`](../../../src/content-view/use-sidebar-webview.ts), [`native OAuth listener`](../../../src-tauri/src/oauth_server.rs)                                        | Resource generations own listener registration and close. Late registrations self-clean; callback listeners enforce state validation and bounded waits.                                                                                                                  |

These are ownership boundaries, not a requirement to introduce a general state-machine framework. A small reducer, queue, generation token or terminal latch is often sufficient. Keep the model beside its implementation and regression tests when extending a lifecycle.

## Reviewing a change

Exercise duplicate admission, reordered completion, cancellation before and after the commit point, unmount/remount, account or document replacement, failure and retry. Test externally visible effects such as token persistence, session publication and resource release, not only component callbacks. Include real-browser coverage when disabled controls, navigation or browser APIs determine the behavior.

Use the workspace-specific commands in the [testing guide](../development/testing.md). Test counts, coverage percentages, bundle measurements and audit findings belong in the pull request that records those runs, rather than in this description of the current architecture.
