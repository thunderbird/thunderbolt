# State-machine audit

Original audit base: `858eceafa`. Audited commit: `ac18e8ff2`. Integrated main: `83117ef6b`. Branch: `codex/state-machine-audit`. Audit date: 2026-11-06.

## Counts and scope

- **76 named lifecycle families inventoried:** 52 changed (including removals), 22 retained, and 2 website families deferred at the user’s request.
- **101 defect families resolved**, listed individually below: 24 from the initial pass, 19 during the branch review, and 58 during the independent second sweep. Related manifestations of one missing ownership boundary count once. This includes issues discovered in the intermediate implementation, not only pre-existing defects.
- **9 redundant state machines removed:** the sync preference mirror, stored onboarding navigation eligibility, MCP’s duplicate raw iroh framing/teardown, the unused automation scheduler, the duplicate name and location forms, persisted OAuth progress indicators, the native filesystem import cache, and legacy Mini App load-order guessing. The necessary wizard, OAuth security state and MCP SDK adapter remain.

A family is an independently owned lifecycle, or an explicitly named group of closely related existing variants. These counts are not counts of booleans, reducer actions, React component instances, or regex matches. Both implicit lifecycles and already explicit models are included so the retained behavior is accounted for. The 52 changed families contained implicit ownership/transition gaps or unnecessary parallel state. The earlier 26-defect tally included an unreachable scheduler and the deferred contact form; those two entries are excluded from the corrected resolved-defect count (B22 and B25 are retired identifiers).

Discovery covered application source in `src`, `shared`, `backend`, `cli`, `src-tauri`, `crates`, and `web`: state/phase/status declarations, multiple hooks, mutable pending/closed/started flags, promise caches, generation counters, timers, stream cancellation and cleanup, and callers of the identified lifecycle owners. Generated dependencies, test fixtures, static content, one-step form values/open toggles, and declarative CI/deployment DAGs are not separate runtime machines in this inventory.

“Deterministic” here means that a fixed ordered sequence of inputs and asynchronous completion events has one defined outcome: only the current owner publishes, terminal transitions settle once, and externally visible effects have an admission rule. Network responses, clocks, operating-system callbacks and user choices remain external inputs. This is a source-and-test audit, not a formal proof that every possible runtime interleaving is correct.

## Retained lifecycle models

These entries were inventoried through source inspection and existing checks; they are not a proof of complete branch or runtime coverage. These owners already had useful state boundaries. Retaining a small reducer, a generation token, a promise queue, or an idempotent terminal latch is simpler than introducing a general state-machine framework. A terminal boolean is appropriate when it actually owns all terminal paths; unrelated field state is not a reason to add a reducer.

### Coverage and practical limits

Regression suites exercise duplicate admission, completion reordering, cancellation, teardown, Strict Mode replay, account/document replacement, failures, retries and phase-specific continuation. Selected final line coverage: key-lock and serial queue **100%**, encryption request boundary **97.83%**, encryption service **92.01%**, key responder **95.88%**, passkey enrollment **97.65%**, account deletion **96.03%**, recovery **89.81%**, passkey removal **82.22%**, HTTP client **93.20%**, auth context **82.80%**, database facade **85.25%**. Coverage percentages are executed-line evidence, not proof of every event ordering.

The key lock serializes writers and cleanup across tabs. It does not turn separate IndexedDB reads into atomic snapshots: codec readers retain their existing cache/invalidation and key-request retry rules, encryption fails closed when a key is missing, and unresolved decode failures preserve opaque data. That reader contract was reviewed and its existing tests retained.

Physical microphone capture, native updater relaunch, real passkey devices, deployed OAuth providers, live PowerSync replication, remote relays, and database-backed multi-device end-to-end flows were not exercised. Rust/WASM is unchanged and was inspected at source level. No claim of zero bugs or exhaustive runtime coverage follows from this audit. No website edits remain.
